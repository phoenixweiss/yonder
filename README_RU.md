# Yonder

Keep it there. Use it here.

[ENGLISH VERSION](README.md)

Yonder — небольшая desktop-утилита, которая хранит файлы в одной обычной папке
хранилища и делает их доступными там, где их ожидают приложения, с помощью
символических ссылок. Хранилище может синхронизироваться любым облачным клиентом;
Yonder не предоставляет собственное облако, учётную запись, сервер или телеметрию.

## Идея

- Настоящие файлы остаются в папке хранилища.
- Ссылки находятся по путям, которые используют приложения.
- Интерфейс сразу показывает оба пути и текущее состояние подключения.
- Существующие файлы никогда не заменяются без явного подтверждения.
- Подключения описываются в человекочитаемом `yonder.yaml`.

## Проверка и применение одной ссылки

Yonder умеет открывать существующее хранилище и проверять его без изменения файлов:

1. Открыть существующее хранилище.
2. Непосредственно показать каждый путь в хранилище и на компьютере.
3. Различить подключённые ссылки, отсутствующие назначения, занятые пути, неверные
   ссылки, отсутствующие файлы хранилища и подключения без настройки для текущей ОС.

Создание нового пустого `yonder.yaml` доступно отдельным путём: перед подтверждением
Yonder показывает выбранную папку, название хранилища и точный путь нового файла.
Выключенная по умолчанию галочка позволяет сразу открыть новое хранилище после
создания; при этом выполняется та же проверка без записи и новых изменений нет.
Для безопасно проверенного отсутствующего назначения Yonder сначала показывает
предпросмотр без записи. Применение остаётся отдельным двухэтапным действием: main
process повторяет все существенные проверки, удерживает открытой проверенную папку
назначения и запрашивает финальное подтверждение. После него небольшой нативный
helper для macOS создаёт ровно одну символическую ссылку. Yonder не создаёт
родительские папки, не заменяет конфликты, не перемещает файлы, не изменяет
`yonder.yaml` и не применяет несколько подключений сразу.

## Конфигурация

`yonder.yaml` имеет строгую версионируемую структуру. Источники задаются относительно
папки хранилища, а назначения — относительно домашнего каталога для macOS, Linux или
Windows. Неизвестные поля, небезопасные пути, повторяющиеся идентификаторы и
пересекающиеся назначения отклоняются до любых файловых операций. См.
[вымышленный пример](examples/yonder.yaml).
При создании хранилища Yonder записывает только новый `yonder.yaml` с пустым списком
подключений и никогда не заменяет существующий файл.
Чтение конфигурации строго ограничено по размеру. Повторная проверка обновляет
показанное состояние, но не создаёт ссылки, не перемещает файлы и не изменяет
конфигурацию.
Renderer никогда не передаёт файловые пути как разрешение на запись. Применение
принимает только идентификатор активного хранилища, идентификатор подключения из
конфигурации и одноразовый token подтверждения. Перед командой создания ссылки
Yonder записывает закрытый локальный append-only журнал. Поэтому неопределённый
результат блокирует слепой повтор. Последующее наблюдение совпадающей ссылки может
закрыть такую запись, а отсутствие ссылки, конфликт или изменение состояния
остаются заблокированными для ручной проверки.

## Техническое направление

Интерфейс — приложение на Vue 3, собираемое Vite и написанное на JavaScript ESM.
Electron служит тонкой desktop-оболочкой: нативные диалоги и защищённый доступ к
файловой системе остаются за узким preload API и не передаются напрямую в renderer.
Проект использует Yarn Classic и намеренно сохраняет небольшой набор зависимостей.

Английский — канонический язык интерфейса и fallback. Русский — первая полная
дополнительная локализация; ресурсы обоих языков сохраняют одинаковую структуру.

Сначала Yonder проверяется на macOS. Linux и Windows учитываются при проектировании,
но не будут объявлены поддерживаемыми до нативной проверки.

Интерфейс начинается с одного компактного окна в светлой теме, вдохновлённой Nord.
Разработка ведётся небольшими этапами с отдельной проверкой каждого из них.

## Разработка

Сейчас для Yonder требуются Node.js 24 и Yarn Classic `1.22.22`. Для нативной сборки
на macOS также используется системный компилятор Clang.

```sh
corepack yarn install --frozen-lockfile
corepack yarn quality
```

Команда `corepack yarn dev` открывает окно Electron, поэтому её следует запускать
только намеренно.

Пользовательские изменения перечислены в [журнале изменений](CHANGELOG.md).
